# 五病种慢性病风险预测完整实施方案

更新日期：2026-10-15。独立阶段已实现队列审核、五病种训练、性能报告和8002服务；网站接入尚未实施。下文保留设计要求，实际结果以报告为准。

当前正式版本为nhefs5-20261015T061013Z，见[性能报告](../reports/training/nhefs5-20261015T061013Z/performance_report.html)。留出集ROC-AUC约0.52至0.61，区分能力偏弱，糖尿病事件较少。现阶段仅为研究原型。

## 1. 目标与实施边界

第一版候选为高血压、糖尿病、卒中、心脏病发作和骨质疏松。采用多标签风险预测：每病独立建队列、训练二分类模型，统一入口执行、统一接口返回。同一人可以对应多个疾病结果，概率不要求相加为1。

当前所有研究工作限定在 `chronic-disease/`。数据、处理代码、训练环境、报告、权重和独立预测服务均留在该目录。现有 `model-training/`、`risk-service/`、`IHMS-admin/`、`IHMS-view/` 和原数据库在独立研究阶段保持原样。

网站接入是独立服务验证后的可选阶段；届时按新增功能实施，不替换现有预警接口或权重。当前仅在独立目录创建环境、训练并验证服务，未执行原数据库迁移或修改前后端。

## 3. 病种、时间和结局定义

| 病种代码 | 展示名称 | 候选字段 | 必须核对的事项 |
| --- | --- | --- | --- |
| hypertension | 高血压 | HYPER、HBPYEAR1及历史、用药字段 | 起点是否已患病，疾病回答与用药、历史预填是否一致 |
| diabetes | 糖尿病（按问卷定义） | SUGRDIAB、DIABYR1及历史、用药字段 | 不能未经证据改名为确诊2型糖尿病 |
| stroke | 卒中／中风 | CVA、STRKYR1、ADDSTRKE等 | 首次与复发分开，不把TIA直接混入 |
| heart_attack | 心脏病发作（按问卷定义） | EVERATT、FIRSTATT、HEARTATK等 | 保持heart attack原义，不扩大为所有心脏病 |
| osteoporosis | 骨质疏松 | OSTEOPOR、OSTEOYR及历史字段 | 医生告知的报告不等同骨密度确诊，检查年份和缺失 |

先审计1987年预测起点、1992年后续随访的任务，默认按预测起点65岁及以上筛选，并记录实际年龄覆盖范围。约五年只是候选调查间隔；需要结合访谈日期、所问时间范围和事件年份确认，不能直接宣称精确60个月发病概率。

第一版目标表述为“起点尚未报告目标疾病的人，在指定后续调查间隔内新报告该疾病的风险”。自报医生告知、基线未诊断、医疗可及性与真实首次发病存在差异，报告和页面保持同一定义。

每病可以有不同的有效队列；某人已有高血压，不妨碍其在满足条件时进入糖尿病队列。所有方向的训练开关在标签审核通过前保持关闭。

## 4. 数据审核与疾病队列

已实现 `src/audit_cohorts.py`，输出 `reports/nhefs/cohort_audit.md` 和JSON汇总；字段核对规则在 `config/nhefs_label_rules.json`，队列构建合并在该脚本内。

执行顺序：

1. 阅读官方PDF手册与SAS布局，核对原始代码对应的“是、否、不知道、拒答、不适用、跳题、代理回答”和历史预填。不得从字段名猜编码。
2. 规范化字符串人员ID，连接1982—1984、1986、1987、1992访谈及追踪状态。1986为特定年龄子队列，不能要求所有人必须出现于该轮。
3. 确认1987预测起点年龄、存活和有效访谈状态；较早记录用于补充起点前病史，不能拿后续信息构造起点特征。
4. 分疾病重建起点状态、首次报告和年份，检查重复、矛盾、跳题、仅有历史预填和年份不完整的情况。
5. 明确1992结果是否有效、其对应时间范围，以及随访前死亡、失访和代理报告状态。
6. 逐病种列出排除原因、年龄分布、有效人数、事件人数、非事件人数、缺失率、随访长度及来源字段，报告各阶段人数流向。

标签与状态约定：

| 情况 | 标签 | 状态 |
| --- | --- | --- |
| 起点确认无病，后续新报告且时间顺序符合任务 | 1 | eligible |
| 起点确认无病，有效随访确认仍无病 | 0 | eligible |
| 起点已患目标病 | null | already_diagnosed |
| 起点病史不明、回答矛盾或结果未能确定 | null | unknown_or_conflicting |
| 失访或未获得适用结局 | null | lost_or_unascertained |
| 随访期间死亡 | 不直接赋0 | deceased，另行审核事件和时间 |

死亡不是“没患病”。如能可靠确定死亡前的疾病事件，可在相应分析设计中使用；不能把死亡者统一转阴性。第一版若只分析完成有效随访的生存者，必须明确这是该选择人群的条件性预测，报告排除人数及选择偏倚，不能直接当作总体老人固定期限发病概率。总体风险研究需进一步处理失访、竞争死亡和事件时间。

进入训练阶段的条件：病种含义与编码明确，起点和后续时间可解释，事件数量足够支撑拟用模型及划分。不能为凑齐5项造标签，也不预设某个统一事件数就保证模型可靠；不足时暂不训练该项并说明原因。

## 5. 特征与可追溯训练数据

已实现以下职责：

- `config/nhefs_feature_schema.json`：原字段、规范字段、时间、编码、单位、缺失策略和在线采集要求。
- `src/audit_cohorts.py`：同时完成每病队列、特征与标签构建，不另设重复脚本。
- `data/nhefs/processed/`：规范化记录、逐病种队列及来源追踪信息，个人级文件留本地。

优先筛选预测起点已经知道、网站也能按同一定义填写的信息。年龄、性别、吸烟、饮酒、活动、体格和其他基线病史均为候选，只有确认实际字段、时间与含义后才能纳入。

1986、1987、1992随访没有新的体格测量，不能把其访谈当成有当年血压、BMI或完整化验。需要较早检查时必须记录测量时间差并证明使用合理；依赖尚未取得的NHANES I检查模块时先补取官方资料。不存在的指标不通过估算变成“实测”。

每病处理以下规则：

- 禁用预测起点之后的诊断、用药、测量和未来回答作为特征。
- 类别、单位、缺失码和异常值规则固定在字段字典中，训练与在线共用。
- 填补参数、编码器、缩放和特征选择只在相应训练折拟合。
- 区分可接受的少量缺失与关键病史不明；后者可导致不予评估。
- 不为凑齐5列标签而把未知值填0。
- 不直接将研究人员记录导入网站用户或老人档案表。

进入下一阶段的条件：每个模型的字段、结局、时间与排除规则可追溯；具备真实可采集的在线输入方案。

## 6. 划分、训练、校准与评价

已实现 `src/train_models.py`、`src/evaluate_models.py` 和 `src/plot_performance.py`，参数、随机种子、搜索结果、区间与依赖版本均写入正式记录。

训练设计：

1. 按人员ID建立统一的数据分组，五个病种复用分组规则，再取各自有效队列；同一人及其多轮记录不能跨训练与最终评价集合。若有强家庭相关性，考虑按家庭分组。
2. 样本允许时预留独立最终评价集，其余作为开发集。具体比例和交叉验证折数由事件数量确定，不先承诺固定比例；任何折缺少阳性或阴性时调整设计或暂停该病训练。
3. 每病先训练逻辑回归基准，与小规模参数搜索的XGBoost比较。有效事件较少时优先控制特征和复杂度。
4. 调参、早停、缺失处理、重采样和校准均在开发流程内完成。校准使用与模型拟合分离的预测数据；需要时使用折外方案，最终评价集不参与模型选择或阈值确定。
5. 类别加权与调查抽样权重分开处理。最终评价保持未人为平衡的留出分布，不把加权训练后的原始分数直接称为人群发病概率。
6. 分疾病评估校准、选择提醒阈值，不能使用旧模型0.7151，也不默认以0.5划分。提醒分档需要依据，未建立分档时仅展示有解释范围的概率。
7. 完成选择后固定模型与版本，对最终评价集进行正式评价；若结果不足则报告未通过，不能继续按最终评价结果反复调参。

每病正式报告至少包含：

| 内容 | 用途 |
| --- | --- |
| 有效人数、阳性/阴性人数、事件比例 | 判断模型与指标的基础 |
| ROC-AUC、PR-AUC | 评价排序表现，结合事件比例解释 |
| 敏感度、特异度、精确率、混淆矩阵 | 评价选定提醒阈值的漏报与误报 |
| Brier分数及校准曲线 | 联合查看概率预测误差与校准，不能只凭Brier判断校准好坏 |
| 不确定性、可支持的年龄/性别亚组表现 | 展示结果稳定性与限制 |
| 与逻辑回归基准、常数事件率基准的比较 | 判断复杂模型是否带来实际收益 |

数据量不足、单一类别或不稳定的指标明确标注不可估计，不能填造数值。解释功能仅描述模型相关因素，不写成已确定病因或治疗建议。

依据：[分组交叉验证](https://scikit-learn.org/stable/modules/cross_validation.html#cross-validation-iterators-for-grouped-data)、[概率校准](https://scikit-learn.org/stable/modules/calibration.html)。

## 7. 模型版本和环境

未来训练使用独立 `chronic-disease/.venv/`；分别锁定训练、推理所需依赖，不升级旧模型虚拟环境。当前下载、提取脚本仍只需标准库。

权重按版本写入：

~~~text
models/<version>/
├─ hypertension.joblib          仅生成审核和评价通过的病种
├─ diabetes.joblib
├─ stroke.joblib
├─ heart_attack.joblib
├─ osteoporosis.joblib
└─ metadata.json
~~~

每个模型包包含预处理和模型；元数据记录训练数据摘要、配置版本、特征、结局、年龄范围、时间定义、校准、阈值、指标、依赖版本和使用限制。训练记录失败或跳过的病种，不能用旧模型代替。

选定版本通过独立配置指定，不自动覆盖既有版本，更不写入 `risk-service/model/`。回退时更改疾病服务选择的版本即可。

在 `reports/training/<version>/` 保留汇总指标和图表；个人级划分、评价输入输出留在被忽略的数据目录。必要的留出评价属于正式模型验证工作，不删除其可追溯记录；不保留临时test脚本、假数据、调试日志或下载残片。

## 8. 独立预测服务

已在 `src/api.py` 实现独立FastAPI研究服务，在 `src/predict.py` 实现加载、校验和预测，监听 `127.0.0.1:8002`。启动前检查端口，现有8001服务保持原接口与模型；当前新模型性能偏弱，不据此开展实际风险决策。

接口建议：

| 接口 | 作用 |
| --- | --- |
| GET /health | 进程、所选模型版本及各病种就绪状态 |
| GET /models | 支持病种、输入要求、适用年龄及预测时间定义 |
| POST /predict/disease | 一次返回5个候选病种的结果状态和可用风险 |

输入以已审核的字段字典为准，包含预测时点可知的人口学/健康信息、明确的三态疾病史（有、无、不清楚）和可用测量时间。未知不能因前端默认开关而变成无病。

每病输出约定：

~~~text
disease_code, disease_name
outcome_definition, horizon_definition
probability, risk_band, threshold
status, missing_fields, reason
model_version, assessed_at
~~~

| status | 含义 | probability |
| --- | --- | --- |
| predicted | 满足该模型适用条件 | 0到1的估计值 |
| already_diagnosed | 起点已有该病 | null |
| insufficient_data | 关键输入或病史不明确 | null |
| not_applicable | 超出模型适用条件 | null |
| model_unavailable | 该病尚未通过训练或模型不可用 | null |

风险分档和阈值只在已建立对应规则时返回；null不转成0。单病模型缺失应给出明确状态，不能导致其他已就绪病种返回虚构结果。

独立验收：同一输入的离线与服务输出一致；单位、缺失、未知病史、已有病史、越界年龄和模型缺失状态正确；重启后可读取指定版本。阶段结束时仍不改网站。

## 11. 数据路线与后续扩展

当前数据源：[CDC/NCHS NHEFS](https://wwwn.cdc.gov/nchs/nhanes/nhefs/default.aspx)。它是较早年代美国人群随访数据，可开发研究原型；中国社区老人的真实风险估计需要匹配人群的独立评价。

CHARLS原始数据尚未取得；若后续按官方流程获批，可评估更贴近中国中老年人群的重新训练与验证。[CHARLS数据入口](https://charls.charlsdata.com/pages/data/111/zh-cn.html)、[申请说明](https://charls.pku.edu.cn/Faq/cjwt.htm)。

CHARLS的2015→2018任务约三年，其病种、编码和人群需重新核对；例如“糖尿病或血糖升高”不能直接替换NHEFS标签。不同队列或不同期限不直接拼接训练。

42个资料方向保留作备查。未来增加任何病种，都需要独立完成A到E；单轮病史、跌倒、住院和不同时间窗不能自动变成同一任务的标签。[多分类与多标签定义](https://scikit-learn.org/stable/modules/multiclass.html)。

临床预测报告可参考[TRIPOD+AI](https://www.bmj.com/content/385/bmj-2023-078378)。本项目第一版为研究原型，不因界面显示概率就获得目标社区人群的验证。

## 12. 已实施的第二轮优化实验

版本为`nhefs5-opt-20261015-v2`，对应配置`config/training_optimized.json`与代码`src/optimization.py`。不修改原前后端、旧风险模型或疾病标签；原版权重和报告完整保留。

1. 基线信息：增加1987问卷的医生告知高胆固醇史、过去一年健康恶化、增重/减重至少10磅及髋部骨折史。来源、特殊编码和问卷页码写入特征配置。`SHEIGHT`实际表示少年时期相对身高，不能当作厘米或用于伪造BMI，因此未使用。
2. 开发方法：比较精简4项、原有和扩展特征组；逻辑回归搜索更强正则化及类别权重，XGBoost搜索浅树、较大叶节点限制与固定正例权重。每病两类模型各18个候选，均在开发集内比较。
3. 嵌套验证：3个外层折，每个外层训练折内进行3折特征/参数搜索，再在该训练折内做sigmoid校准。外层预测不使用该人的标签来选参数、筛特征或校准。全开发集最终搜索完成后拟合版本模型；家庭选择依据外层折外AUC，AP作并列比较。开发集选择分数仍不能当作最终无偏性能。
4. 阈值：默认在开发集特异度≥80%的候选中最大化Youden指数，以限制大量误报；另外保留平衡Youden、敏感度≥70%和F1最大化三种策略。它们是研究操作点，尚未验证临床效用，开发集约束不保证评价集达到。
5. 结果交付：所有原有指标和混淆矩阵继续输出，另存四种阈值表、与原版的配对AUC变化区间、准确率/召回/误报对比，以及原模型更改阈值和新模型使用原召回策略的参照，区分排序改变与阈值取舍。
6. 评价边界：原留出结果此前已查看，本轮复用只能作探索性优化比较。队列人员、标签和划分与原快照逐条核对，未合成病例、未重新划分“挑好看的结果”。后续仍需新数据验证。
7. 使用隔离：优化训练不自动更换活动模型，必须显式`--activate`或通过环境变量在其他端口加载。依赖、模型、个人级数据与报告继续保存在`chronic-disease/`。
