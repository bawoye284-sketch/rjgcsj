# 数据集样本用户导入

`import_nhefs_users.py` 将原始 NHEFS 审计队列中 `split=evaluation` 的全部参与者导入本机 MySQL，供系统演示、资料查看和手动发起预测使用。原始测试集包含1,608条病种记录、407位参与者；同一人只建立一个用户。

本工具读取 `IHMS-admin/src/main/resources/application.yml` 中的数据库配置，密码只传入 MySQL 子进程环境变量，不写入导入报告或命令行。仅支持本机 MySQL。脚本使用 Python 标准库及 PyYAML，MySQL 客户端优先从PATH查找，其次查找Windows默认安装位置；可用 `--mysql` 指定。

先预检查，确认目标库、人数、账号冲突及重复导入情况：

```powershell
python -B .\chronic-disease\tools\import_nhefs_users.py
```

实际导入：

```powershell
python -B .\chronic-disease\tools\import_nhefs_users.py --apply
```

如果运行环境没有 PyYAML，可以使用已有的、安装了 PyYAML 的 Python；也可以通过 `--password-env <环境变量名>` 与 `--host`、`--port`、`--database`、`--user` 指定连接，不读取YAML。不要把真实数据库密码写进脚本、命令文本或报告。

## 数据落点

| 数据表 | 保存内容 |
|---|---|
| `user` | 普通用户账号 `nhefs_<原参与者编号>`，昵称为随机生成且不重复的常见中文姓名，角色2 |
| `elder_disease_profile` | 年龄、性别、体重、自评健康、生活习惯等12项基线特征 |
| `elder_disease_history` | 每人5项基线疾病史，来源 `NHEFS_1987`；未知保留NULL |
| `dataset_user_source` | 新建的来源映射表；保留原参与者编号、原始划分、SHA256及完整原始病种记录 |

初始样本密码统一为 `123456`，使用与项目既有账号相同的密码摘要格式。示例：`nhefs_00002` / `123456`，在普通用户登录入口登录。

昵称仅为样本展示用的虚构姓名，由常见姓氏和名字组合生成，全部使用汉字，不带编号、字母或符号；不代表数据集参与者的真实身份。姓名和登录账号分开保存，修改昵称不会改变账号、用户编号、健康资料或来源记录。

这里导入的是原始审计队列的全部 `evaluation` 记录，并非后来按单个现有权重成员生成的较小测试子集。导入数据库不会改变任何训练数据、模型权重或网站模型版本。

原资料对应历史问卷基线，页面所示年龄与病史代表该基线记录。随访发病标签仅存入来源记录，不当作基线疾病史，也不冒充模型预测。缺少的BMI、血压、心率、血氧等不补造；需要个性化模型预测时，应在用户端补齐实际资料和生理测量。

管理员可以在用户管理或联合评估管理中搜索 `nhefs_` 查看导入用户；登录对应用户后可在健康风险评估页查看资料并发起慢性病预测。导入本身不创建预测结果或医生咨询关系，医生端仍按原有医患咨询关联控制访问。

## 重复执行和记录

脚本以数据集、参与者编号和源文件摘要核对已导入用户，重复执行跳过已有记录；遇到账号冲突、已导入资料结构异常或源文件变化时停止，不覆盖已有用户。业务插入在InnoDB事务内完成，错误时回滚；来源表首次创建是单独的建表操作。

每次执行 `--apply` 后在 `chronic-disease/reports/database-import/nhefs-evaluation-<时间>/` 保存导入清单和 `users.csv` 账号映射。清单不含真实数据库凭据。首次导入后已核对407份资料和2,035条病史的字段值、空值、来源标签，并验证样本登录及管理员列表。

## 模拟补充资料与批量预测

`populate_sample_assessments.py` 面向上述导入的样本用户，按用户生成可复现的模拟补充字段，并通过网站后端实际执行两类预测。它不会向其他已有用户写入数据，不修改模型权重或随访标签。

```powershell
# 预检查数据库和后端模型状态
python -B .\chronic-disease\tools\populate_sample_assessments.py

# 补齐样本资料，并为每人保存一份个性化评估与一份五病种评估
python -B .\chronic-disease\tools\populate_sample_assessments.py --apply
```

执行前启动MySQL和Java后端，确认六个模型已就绪。脚本使用与导入工具相同的数据库配置读取方式，也支持 `--password-env` 等参数；`--workers` 默认3，最多4。

已存在的非空基线字段原样保留，仅缺失字段进行模拟补充；新建BMI和六项数值测量。若用户已有测量，则保留最近测量中的非空数值。随机种子来自批次与参与者编号，不读取随访发病标签，也不根据预测结果反复抽取输入。

随机范围仅用于展示软件功能，不代表临床数据分布。完整生成方案、原始资料快照、填充字段清单和评估编号保存在 `reports/database-import/nhefs-simulated-v1/`，并写入 `dataset_user_source.source_payload_json` 的独立 `simulation` 分支，原始基线及随访数据保留。两类评估的输入快照带 `dataOrigin` 标记，结果说明包含“本记录包含随机生成的模拟补充资料，仅用于系统演示。”。

脚本先调用正常的用户登录、资料保存和评估接口，再补充来源标记。预测概率、阈值与风险等级由当前网站模型返回，不人工填写。已有疾病史的病种按在线规则保留“已有病史”状态，不强行产生新发病概率。

每人保存固定输入方案和固定UUID请求号，断点后可再次运行；正常接口按请求号去重，避免重复生成测量和评估。若用户在此期间修改了健康档案，脚本停止处理该用户，避免覆盖其修改。

若上次汇总存在失败用户，可用 `--apply --retry-failed` 只补齐失败项。Windows的OneDrive短暂占用JSON文件时，脚本会自动重试原子写入。逐人方案与结果是本地断点文件，不纳入Git；汇总和核验报告保留。

已完成批次 `nhefs-simulated-v1`：407位用户、407份个性化评估、407份慢性病评估、407条生理测量及2,035条病种结果。其中1,687项为模型预测，348项因已有相应病史保留“已有病史”状态。管理员在联合评估管理搜索 `nhefs_` 可查到814条评估；用户登录后可读取自己的两类最新结果。完整结果与核验见该批次的 `summary.json` 和 `verification.json`。

## 指定用户的近30天模拟趋势

`add_user_risk_timeline.py` 为指定普通用户追加分布在过去30天的模拟生理测量，并由当前个性化模型逐次计算预测。既有测量、评估和基础档案保留，每次预测仅参考时间早于当次测量的历史记录。

```powershell
python -B .\chronic-disease\tools\add_user_risk_timeline.py --account lty --count 60 --days 30 --apply
```

时间与数值方案固定保存在 `reports/database-import/timeline-lty-60-30-v1/plan.json`；`predictions.json` 保留真实模型输出及当次快照，`summary.json` 和 `verification.json` 记录数量及校验。模拟记录的说明和快照带来源标记，不能作为真实手环测量。脚本先完成全部模型调用，再在一个事务中追加测量与评估；重复运行同一批次不重复插入。

本次为 `lty` 追加60条预测和60条测量，覆盖2026年9月18日至10月17日，累计63条测量、62条个性化评估。用户、医生和管理员共用的趋势组件展示所选天数内的全部有效记录，按实际时间定位，减少常驻数值标签并保留逐点悬停详情。
