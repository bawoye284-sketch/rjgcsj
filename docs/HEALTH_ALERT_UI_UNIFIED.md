## 颜色映射

| 后端等级 | 文字标识 | 颜色 |
| --- | --- | --- |
| NONE | 未触发规则预警 | 继承原有文字色，不加警示底色 |
| GENERAL | 普通异常提醒 | #D97706 |
| REPEATED | 连续测量异常；本次测量另加“需要关注” | #EA580C |
| EMERGENCY / SOS事件类型 | 紧急求助 | #DC2626 |
| 测量事件 RECOVERED | 测量已恢复 | 中性默认文字色；历史等级也不再高亮 |

预警标识使用19px粗体以提高指定橙色在浅色背景上的可读性；颜色同时配有文字，没有整行着色。检测中、待确认、已确认收到、已处理等不借用风险等级的颜色。未知状态不猜测为正常或成功。

## 展示依据和边界

- 颜色仅读取后端 level、SOS类型及恢复状态；不会根据显示文字判断等级。
- 缺测、无配置、未启用和历史不足逐项说明。全部指标未参与有效检查时标题为“本次测量暂未完成有效预警判断”，不声称正常。历史不足不推断健康恶化。
- 后端目前没有单独的触发原因代码，超范围、连续次数和近期变化的自然语言转换只识别后端现有明确原因格式；未识别的历史原因保留原文。前端不比较阈值、不重新计算次数或变化，不从配置次数推断实际连续次数。
- UNCONFIGURED 仍保留在接口原始数据中；前端开发控制台记录指标键、状态和规则版本，不输出测量值、联系人信息或身份编号。后端原有诊断记录未变。当前接口不细分“缺少范围”和“映射不唯一”，用户说明不会伪称具体技术根因。
- 通知任务接口没有当前预警是否恢复的信息，故列表列名明确为“提醒类别（生成时）”，展示生成通知时的 GENERAL/REPEATED/SOS 阶段；不能把它当作患者当前风险。当前风险以测量/医生预警页面为准，没有新增查询或修改后端语义。
- 已处理SOS按真实RESOLVED显示“已处理”，类型仍红色。只有真实确认状态/确认记录才显示医生确认；直接记录处理结果时不补造确认事实。
- 时间格式统一应用于测量及历史更新时间、通知创建和发送尝试时间、SOS创建/确认/处理时间、医生详情及操作时间。无时间显示“—”，无效时间不伪造日期；带时区的时间转换为浏览器本地时间。日期筛选仍为原来的日期筛选，参数不变。医生原始备注中自行填写的日期文本不改写。

## 浏览器人工复验

1. 刷新已运行前端，或在 IHMS-view 运行 `npm.cmd run serve`；使用现有演示后端，不需要数据库升级。
2. 用户健康评估页查看正常测量：默认文字色，无绿色/警示底色；缺测、未配置、历史不足应分别说明。按当前演示参考范围选输入，不要把未配置视为正常。
3. 查看已存在的单项异常和连续异常：分别为橙黄色和深橙色，检查实测值、单位、参考范围及原因。连续次数只在记录中确有该信息时出现。近期变化记录应写“近期变化提醒”，不强行解释为超范围。
4. 展开历史预警，检查旧记录、分页、刷新和恢复状态：恢复后文字中性，历史原因仍保留。
5. 打开个人中心通知记录：查看“我的站内消息/关联医生/紧急联系人”、首次/后续提醒、模拟完成/等待/失败/取消/未知。主列表无编号或重试比例；展开详情可见原事件编号及发送次数。顶部只提示一次发送不等于查看或确认。
6. 用户求助页查看现有已确认和已处理记录：类型红色、状态准确，已处理不显示等待确认。通知发送与医生响应仍分别展示，演示提示和当地急救安全说明保留。
7. 医生患者预警列表：普通/连续/SOS颜色一致；找一条已恢复但尚未确认的记录，风险状态为中性“测量已恢复”，处理状态单独为“待确认”。筛选、日期、分页、详情按钮正常。
8. 医生详情检查原始处理说明未被改写，表头为医生姓名、处理状态、处理说明、操作时间；确认收到不显示为已处理。
9. 检查以上页面所有系统时间均显示到分钟，不包含秒或微秒；在常见电脑宽度下检查换行和表格可读性。

验收只需使用演示数据；不需要真实外发邮件、拨号或变更阈值。完成后停止，等待用户浏览器验收。
