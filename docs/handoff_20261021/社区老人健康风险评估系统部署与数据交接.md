# 社区老人健康风险评估系统部署与数据交接

交接日期 2026年10月21日

本文供接手项目的开发同事在 Windows 新电脑上安装依赖、恢复现有业务数据并启动系统。按本文完成数据库导入、配置和前后端启动，即可使用现有六个模型进行联合预测，无需重新训练。

## 二 首次安装依赖

先安装 JDK 17、Maven、带 npm 的 Node.js、Python 3.13 和 MySQL 8.0，同时安装 MySQL 命令行客户端。Node.js 可按上页本机版本复现。安装后重新打开 PowerShell，确认命令能找到对应工具。

```powershell
java -version
mvn -version
node --version
npm.cmd --version
py -3.13 --version
```

java 与 mvn 输出中的 Java 主版本均应为17。系统有多个 JDK 时，设置 JAVA_HOME 为 JDK 17 安装目录并重新打开终端。IDEA 的 Project SDK、Maven Importer 和 Maven Runner 也选17。

### 1 安装联合推理依赖

从项目根目录创建新的虚拟环境。压缩包不携带本机 .venv，同事电脑需要重新创建，避免原解释器绝对路径失效。

```powershell
Set-Location 'C:\IHMS\rjgcsj'
py -3.13 -m venv .\chronic-disease\.venv
& .\chronic-disease\.venv\Scripts\python.exe -m pip install `
  -r .\chronic-disease\requirements-lock.txt
& .\chronic-disease\.venv\Scripts\python.exe -m pip check
```

requirements-lock.txt 固定完整依赖，包含 FastAPI、Uvicorn、pandas、scikit-learn、XGBoost 和 joblib。安装命令成功结束后再启动后端。网站推理只需这一套环境；根目录 .venv 主要供旧离线训练使用。

### 2 安装前端和后端依赖

```powershell
Set-Location 'C:\IHMS\rjgcsj\IHMS-view'
npm.cmd ci
Set-Location 'C:\IHMS\rjgcsj\IHMS-admin'
mvn -DskipTests package
```

npm ci 按 package-lock.json 安装；锁文件变更时再执行。Maven 按 pom.xml 下载依赖并打包，首次需要联网。构建产物是 IHMS-admin/target/personal-health-api-1.0-SNAPSHOT.jar。package 是打包操作，本手册不将跳过测试的构建称作测试通过。

压缩包不携带 node_modules、Maven 本机缓存、target、日志和 IDE 设置。npm 与 Maven 的依赖重新安装；训练权重和模型数据随包保留。

## 三 恢复交接数据库

本次快照来自 personal_health，包含25张表、220个字段、7778条记录，文件约7.38 MiB。导出核对完成时间为2026年10月21日19时57分，时区为北京时间；后续业务新增数据不包含在此快照中。

导出使用一致性事务，保留建表定义、索引、自增值、中文数据和现有业务记录。不包含数据库服务的 root 账号密码；同事连接自己的 MySQL 账号。SQL 不指定 USE 原数据库，也不包含 DROP TABLE，可恢复到另一个新库名。

### 1 使用配套程序导入

启动本机 MySQL 服务。关闭目标项目后端，打开 PowerShell，在项目根目录执行。程序会交互询问同事电脑的 MySQL 密码，密码不写入命令参数。

```powershell
Set-Location 'C:\IHMS\rjgcsj'
$restore = '.\docs\handoff_20261021\database\restore_database.py'
py -3.13 $restore --user root --database personal_health
```

程序先核对 SQL 文件 SHA-256，再新建数据库并导入，最后逐表比较记录数、字段数和逻辑数据摘要。成功时输出 PASS 和25张表、220个字段、7778条记录。校验清单与SQL文件需保留在同一目录。

如果 personal_health 已存在，程序会拒绝覆盖。改用新库名，并在下一章将 MYSQL_URL 的库名同步修改。

```powershell
py -3.13 $restore --user root --database personal_health_handoff
```

如果找不到 mysql.exe，显式传入客户端位置；路径因安装版本不同而调整。

```powershell
$mysql = 'C:\Program Files\MySQL\MySQL Server 8.0\bin\mysql.exe'
py -3.13 $restore --mysql $mysql --user root `
  --database personal_health_handoff
```

### 2 使用 Navicat 或 Workbench 导入

新建一个空库，字符集 utf8mb4，排序规则 utf8mb4_0900_ai_ci。选中该库，运行 personal_health_20261021.sql，等待执行完成。随后对照 table_counts.csv 检查各表记录数。已有同名库时应先另建新库，完整快照导入后无需再依次执行 sql 目录中的历史初始化和升级脚本。

已在独立临时库中试导入本快照，25张表的建表定义、记录数和全部行内容摘要一致；临时校验库已清理，原业务库未修改。完整核验记录在 database_manifest.json。

## 四 配置数据库与本地服务

### 1 生成本机配置

交接包不包含原电脑带凭据的 application.yml 和 application-demo.yml。从项目根目录复制模板，仅在本机配置不存在时执行，避免覆盖同事已填写的内容。

```powershell
Set-Location 'C:\IHMS\rjgcsj'
Copy-Item .\IHMS-admin\src\main\resources\application.yml.example `
  .\IHMS-admin\src\main\resources\application.yml
Copy-Item `
  .\IHMS-admin\src\main\resources\application-demo.yml.example `
  .\IHMS-admin\src\main\resources\application-demo.yml
```

### 2 配置 MySQL 模式

在用于启动后端的 PowerShell 中填写本机数据库连接。先按提示读取密码；数据库名必须与第三章导入时使用的库名一致。

```powershell
$env:MYSQL_USERNAME = 'root'
$secureDbPassword = Read-Host '本机MySQL密码' -AsSecureString
$env:MYSQL_PASSWORD = [System.Net.NetworkCredential]::new(
  '', $secureDbPassword).Password
$jdbc = 'jdbc:mysql://127.0.0.1:3306/personal_health'
$env:MYSQL_URL = $jdbc + '?useUnicode=true&characterEncoding=UTF-8' +
  '&serverTimezone=Asia/Shanghai'
```

这些环境变量只对当前 PowerShell 及其启动的后端生效。新开终端需重新设置，也可以在本机 application.yml 中填写 spring.datasource 的 url、username、password。原作者数据库密码不用于同事电脑。

模板默认配置为 demo，原电脑本机配置为 mysql；启动时必须显式选择模式。要使用导入的数据，在 Maven 参数或 IDEA 程序参数里指定 mysql。03_start_demo_backend.bat 始终指定 demo，会打开另一套 H2 数据。

### 3 模型与外部问答配置

模型默认地址为127.0.0.1:8001；Java 默认查找 chronic-disease/.venv/Scripts/python.exe。通常无需增加模型环境变量。目录识别失败时，在启动后端的同一终端设置：

```powershell
$env:IHMS_PROJECT_ROOT = 'C:\IHMS\rjgcsj'
$env:IHMS_MODEL_PYTHON =
  'C:\IHMS\rjgcsj\chronic-disease\.venv\Scripts\python.exe'
```

DeepSeek 问答依赖独立的 DEEPSEEK_API_KEY，可由同事配置自己的密钥。六个本地预测模型不需要该密钥。更换前端访问主机时，同时修改 IHMS-view/src/utils/request.js 中写定的 localhost API 地址，并核对后端跨域配置。

## 五 日常启动与停止

### 1 启动正式后端

先启动 MySQL，确认第三章已导入数据。保留第四章设置过数据库变量的终端，执行：

```powershell
Set-Location 'C:\IHMS\rjgcsj\IHMS-admin'
mvn spring-boot:run '-Dspring-boot.run.profiles=mysql'
```

也可在 IDEA 打开 IHMS-admin/pom.xml，JDK选17，运行 com.star.Application。工作目录设为 IHMS-admin，程序参数填 --spring.profiles.active=mysql；数据库变量在 IDEA Run Configuration 中设置，或写入本机 application.yml。

使用打包方式时，保持项目目录和模型目录存在，在 IHMS-admin 执行下列命令。仅复制一个 JAR 不包含 Python 环境和外置模型权重。

```powershell
java -jar .\target\personal-health-api-1.0-SNAPSHOT.jar `
  --spring.profiles.active=mysql
```

后端监听21090，自动启动8001上的联合模型服务。日志出现六个模型就绪后再执行预测，启动等待默认最长90秒。模型加载日志位于 IHMS-admin/logs/model-runtime.log。

### 2 在另一个终端启动前端

```powershell
Set-Location 'C:\IHMS\rjgcsj\IHMS-view'
npm.cmd run dev:compatible
```

也可双击04_start_demo_frontend.bat；这个脚本名称带 demo，但它只启动前端，数据库模式由后端决定。浏览器打开 http://localhost:21091，登录后进入 /health-assessment。

### 3 检查模型状态

```powershell
$health = Invoke-RestMethod 'http://127.0.0.1:8001/health'
$health | ConvertTo-Json -Depth 6
```

应看到 service 为 unified-health-risk，ok 为 true；personalized.ok 为 true；chronic.ready_count 与 expected_count 均为5，chronic.model_version 为 nhefs5-opt-20261015-v2。接口文档位于 http://127.0.0.1:8001/docs。

### 4 H2 演示与关闭

只体验页面时，可双击03_start_demo_backend.bat，再双击04_start_demo_frontend.bat。H2数据保存在 IHMS-admin/demo-data，与本次MySQL快照分开。H2示例用户 demo_elder、管理员 demo_admin、医生 demo_doctor 的密码均为123456；医生需切换医生登录。这些示例凭据不代表MySQL库中存在相同账号。

停止时在前端和后端终端分别按 Ctrl+C。Java会清理自己启动的模型进程；自行独立启动的兼容模型服务需要在对应窗口关闭。日常无需运行02_start_model_service.bat，也无需另起8002。

## 六 最终模型说明与版本对应

最终 Word 说明继续作为训练过程和图表来源的交接依据。以下列出其关键统计范围，便于接手同事将文档、线上模型和独立实验对应起来。

### 1 个性化生理预警

来自 PhysioNet 2012 Set A 的筛选住院队列，前24小时构造特征，后24至48小时制作五项综合代理标签。五项计分不含吸氧和意识状态，不等同完整 NEWS2。模型为XGBoost，在线版本 numeric5-future-aggregate-v2-grid。

| 划分 | 人数 | 预警类人数 |
| --- | --- | --- |
| 训练集 | 445 | 46 |
| 验证集 | 82 | 14 |
| 测试集 | 91 | 12 |

固定测试集准确率93.41%，召回率66.67%，精确率80.00%，F1为0.727，ROC AUC为0.895。混淆矩阵为TN77、FP2、FN4、TP8。权重和指标分别在 risk-service/model/five_score_future_model.joblib 与 metrics.json。

### 2 五病种队列与文档实验

NHEFS 以1987年为基线、1992年为后续访谈，起点年龄65岁及以上。五个病种分别筛选，人数不能相加视为不同老人的总数。

| 病种 | 可用人数 | 原开发人数 | 原评估人数 | 文档实验准确率 |
| --- | --- | --- | --- | --- |
| 高血压 | 870 | 699 | 171 | 97.66% |
| 糖尿病 | 1852 | 1492 | 360 | 99.44% |
| 卒中 | 1899 | 1533 | 366 | 98.91% |
| 心脏病发作 | 1826 | 1482 | 344 | 99.13% |
| 骨质疏松 | 1928 | 1561 | 367 | 99.18% |

上述准确率来自 overlap-20261017-demo 的 ExtraTrees 实验。实验将部分原评估人员纳入拟合后，仍在全部原评估人员上统计，属于非独立实验评估。原开发人数不是该实验最终拟合人数；实际纳入成员见实验成员清单。高分不能替代网站部署版本的独立评估结果。

### 3 网站实际加载版本

网站使用 nhefs5-opt-20261015-v2，逐病种选择逻辑回归或XGBoost，路径为 chronic-disease/models/nhefs5-opt-20261015-v2。线上固定版本由联合服务和Java配置指定；models/active_model.json仍指向旧基线，仅检查该指针不能判断网站版本。以8001健康检查实际返回为准。该优化版本的健康状态标记为已查看留出集的探索性复用，不能将其当作全新独立外部验证。

两套权重与报告都随完整项目保留。文档图表重绘不会切换网站模型。数据库中的历史结果也不会因重绘而重算。当前模型用于研究展示，社区老人场景仍需独立验证。

## 七 模型资产与训练数据的位置

### 1 运行时需要保留的文件

risk-service 整个目录、chronic-disease/src、chronic-disease/config 以及线上模型版本目录应与Java工程保持同一项目结构。线上慢性病目录包含 metadata.json 和各病种候选权重，完整保留该目录，避免元数据引用的文件缺失。

### 2 需要复现时再训练

首次启动网站无需训练。若要重新训练个性化模型，先另建根目录训练环境；命令从项目根目录执行。

```powershell
py -3.13 -m venv .\.venv
& .\.venv\Scripts\python.exe -m pip install `
  -r .\model-training\requirements.txt
& .\.venv\Scripts\python.exe `
  .\model-training\train_five_score_model.py
```

训练输出到 model-training/output/news2-five-score，不自动替换在线权重。重新从原逐小时数据制作个性化标签时，默认来源为项目旁 sjj/逐小时数据/news2_hourly_numeric_components_0_48h.csv；该项目外文件不在交接包内。已生成标签与划分保留，可从已保存的训练输入重新训练。更换数据来源时使用构造脚本的 --source 参数。

慢性病完整训练入口为 chronic-disease/src/run_pipeline.py，使用chronic-disease/.venv；默认生成新版本，不自动替换活动指针。文档ExtraTrees实验入口为 chronic-disease/experiments/overlap-demo/run_experiment.py，精确复核原图表时应读取已保存run的预测和指标，而不是将新一次运行当作原版本。

慢性病数据清单见 data/nhefs/download_manifest.json，队列规则见 reports/nhefs/cohort_audit.json。所有训练前需保留旧权重、阈值、配置和报告；变更部署版本后重启后端并重新核对健康检查。

## 八 接手后的验收与故障处理

### 1 最小验收顺序

1. 数据库导入程序输出PASS；确认25张表、220个字段和7778条初始记录。启动并写入新记录后，总数会变化。
2. 后端使用mysql配置启动且无连接错误，8001健康检查显示六个模型就绪和指定慢性病版本。
3. 前端21091可以打开，使用移交业务账号登录。业务账号密码沿用原账号，由交接双方单独确认；本次不重置账户或修改原密码。
4. 老人用户进入健康风险评估，填写基础资料、五项病史及本次实测值，点击保存并联合预测，两类结果或跳过原因能同页显示，历史可查询。
5. 关联医生进入患者健康管理，只能查看与自己存在咨询关系的患者；管理员进入联合评估管理，可以检索历史、资料及模型状态。
6. 保存一次记录，正常关闭并重启Java后端，再次登录确认记录仍在，以验证连接的是已导入的MySQL库。

联合预测时，年龄和性别共用；个性化需要BMI和至少一项本次实测；慢性病需要体重、自评健康、吸烟、饮酒、运动至少两项，并明确对应疾病史。当前慢性病研究范围为65至90岁。未知病史、有病史、资料不足和年龄不适用导致的跳过有各自原因，不等于服务故障。

### 2 常见问题

| 现象 | 处理方式 |
| --- | --- |
| 导入程序提示库已存在 | 换新库名，并同步MYSQL_URL中的库名 |
| 导入提示未知排序规则 | 使用MySQL 8.0，避免直接按MySQL 5.7或MariaDB导入 |
| 页面没有交接数据 | 核对后端是否使用mysql，是否误开H2演示脚本 |
| Access denied或连接失败 | 核对本机MySQL服务、端口、账号密码与环境变量所在终端 |
| No module named或预测503 | 按第二章向chronic-disease/.venv安装锁定依赖，检查模型日志 |
| 模型版本不匹配 | 查8001端口占用与手动旧服务，关闭自行启动的旧服务后重试 |
| 找不到mvn或Java编译失败 | 配置PATH与JAVA_HOME，确认Maven实际使用JDK17 |
| cross-env找不到 | 在IHMS-view重新成功执行npm.cmd ci |
| OpenSSL相关前端启动错误 | 使用已带兼容参数的npm.cmd run dev:compatible |
| localhost在同事浏览器无效 | 它表示浏览器所在电脑；跨机使用时修改API地址及访问配置 |

### 3 后续备份

变更结构或批量操作前先备份。可在MySQL工具中对当前业务库导出结构与数据。命令行导出可使用mysqldump的一致性事务参数；指定新文件并检查退出状态，避免用PowerShell旧版文本重定向破坏UTF-8。数据库备份不包含Python权重，权重与版本元数据需另外保存。

本次交接包含账户与健康记录，仅在授权同事之间传递。校验文件记录SHA-256，传输后可以核对文件是否完整。原电脑的数据库密码和外部问答密钥未随项目配置打包。
