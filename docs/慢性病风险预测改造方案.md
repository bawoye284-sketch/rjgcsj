**社区老人慢性病风险预测改造方案与数据集清单**

编制日期：2026-10-14；数据获取进展更新于 2026-10-15。当前运行模型仍为五项综合分预警模型；CHARLS 原始数据尚未取得，NHEFS 官方公开随访数据已经下载，尚未训练疾病模型。

**按“可直接下载”的要求，先处理已取得的 NHEFS；CHARLS 保留为更贴近中国人群的授权数据路线。**

NHEFS 数据已保存到 `model-training/data/nhefs/`，含 11 个原始文件、23 个字段说明和手册，共约 313 MB。人员追踪表有 14,407 人；各文件人员 ID 已按官方布局核对，尚不能据此确定最终老年训练人数和疾病事件数。详见 [已下载数据与使用说明](../model-training/data/nhefs/README.md)。

NHEFS 是 [CDC/NCHS 的公开人群随访数据](https://wwwn.cdc.gov/nchs/nhanes/nhefs/default.aspx)，包含 1982—1984、1986、1987、1992 年访谈，以及住院记录和追踪状态。可先审计 1987→1992 的约五年任务，病种与期限须由真实编码、既往病史、事件时间和随访情况确定。原方案下面的 CHARLS 2015→2018 字段与约三年期限，不能直接套用到 NHEFS。

NHEFS 是历史美国人群数据；用于中国社区老人仍有人群与年代差异。下载的 NHEFS 随访文件也不等于完整 NHANES I 基线检查数据，所需基线化验或其他模块应按最终特征另行补取。此次下载不自动替换网站模型。

CHARLS 路线的第一版候选目标为高血压，以及问卷定义的“糖尿病或血糖升高”。心脏病作为候选扩展项，需要确认标签一致性和新报告病例数。NHEFS 另有自身的疾病问题与编码，应独立确定名称和队列。每个目标分别建立二分类模型；同一人可以有多个疾病结果，各疾病概率不要求相加为 1。

若使用 CHARLS 问卷，准确的第一版任务是“基线尚未报告目标疾病的人，在后续调查中新报告医生告知该疾病的风险”。自报的首次诊断报告与经过病历核实的真正首次发病存在差异，尤其要考虑基线未诊断者。目标名称与论文结论应保持这一限定。

**CHARLS 路线：获批后的下载清单。**

建议从 2015 年基线资料与 2018 年后续调查开始，形成约三年的调查间预测任务。实际时长应按访谈日期审核。只有调查年份或诊断年份时，不能宣称精确的 36 个月发病概率；无准确事件时间时应表述为随访间新报告风险。

| 年份 | 优先下载模块 | 作用 |
| --- | --- | --- |
| 2015 | 基本信息 | 年龄、性别及可用人口学资料 |
| 2015 | 健康状况与功能 | 基线疾病状态、生活习惯等候选特征 |
| 2015 | 体检信息 | 血压、体格指标等，按实际字段确认 |
| 2015 | 血检数据及血检发布说明 | 评估能否建立带实验室检查的增强模型 |
| 2015 | 样本信息、样本权重 | 身份匹配、调查设计及人群解释 |
| 2018 | 基本信息、健康状况与功能、样本信息及权重 | 匹配后续受访者，重建疾病报告与随访状态 |
| 两轮 | 家户问卷、编码参考书、用户手册或发布说明 | 明确字段语义、跳题、单位、缺失码和 ID 匹配 |

优先下载两轮完整数据包，并另外确认 2015 血检包是否包含在已取得文件中。数据通常以 Stata 格式提供，可用 pandas.read_stata 读取，不必为了训练先导入 MySQL。

2015 血检文档列出了血糖、HbA1c、血脂、肌酐等指标，并说明可通过 ID 匹配；跨轮 ID 处理应遵循发布说明。[2015 血检说明](https://charls.pku.edu.cn/sj/xuejianshujufabushuoming2015.pdf)

CHARLS 每轮模块并非完全相同，不能假定每轮都存在同样的体检或血检。2020 等后续轮次待第一版数据盘点后决定是否加入，不直接将不同随访长度的标签合并。

**疾病标签与数据清洗规则。**

1. 将调查受访者 ID 保留为字符串，按发布说明规范化；校验跨轮匹配率、重复记录及家庭关系。
2. 分疾病重建基线状态，综合适用的当轮回答、历史预填、追访确认和既往治疗记录。未知与跳题不能自动当作未患病。
3. 仅对基线符合该疾病风险队列条件的人建立该疾病标签。基线已报告该病的人可接受其他疾病预测，该病状态显示“已有病史”，不返回其新发风险。
4. 基线无该病、后续新报告且时间关系一致，记为 1；随访有效且仍无该病，记为 0；缺失、拒答、矛盾、失访、死亡等分别记录状态，不强制记为 0。
5. 第一版若只能分析完成随访者，必须明确这是该选择人群中的新报告预测。若要估计总体固定期限发病风险，应进一步处理失访、死亡竞争风险及事件时间问题。
6. 不使用预测时点之后的检查、用药、诊断或未来疾病回答作为输入。其他疾病的基线病史可按任务定义作为候选输入。
7. 建立字段字典：原变量、轮次、含义、单位、编码、缺失规则和时间。血检中 mg/dL 与页面可能使用的 mmol/L 等单位必须在训练和在线服务中一致处理。
8. 每个疾病可以有不同的有效样本与缺失标签掩码，不为凑齐多标签表而填造标签。

问卷证据：[2015 家户问卷](https://charls.pku.edu.cn/sj/jiahuwenjuan2015.pdf)、[2018 家户问卷](https://charls.pku.edu.cn/sj/jiahuwenjuan2018.pdf)。其中“糖尿病或血糖升高”不能直接命名为确诊 2 型糖尿病；广义心脏病也不能直接命名为冠心病。

第一阶段先报告每病的基线排除人数、匹配人数、有效随访人数、新报告病例数、阴性人数和缺失率，再决定能否训练、是否缩减病种或特征。NHEFS 已取得原始文件，但尚未完成疾病队列审计；CHARLS 尚未获批下载。不能预先承诺有效样本数和准确率。

**训练与验证方案。**

- 分病种比较逻辑回归基线与 XGBoost；先按有效事件数量控制特征和参数搜索规模。
- 优先建立可在网站中实际采集的基础版特征；如果血检覆盖足够，再评估增强版。不能依靠大量估算填补掩盖用户完全没有关键检查资料的情况。
- 以人员为单位划分训练、调参和最终评价数据；同一人的多轮记录不得跨集合。家庭内相关性较强时考虑家庭分组。
- 若增加时间留出评价，核对任务期限与输入定义的一致性，并明确同一人是否重复出现；它不自动等于独立外部验证。
- 填补、编码、特征选择、重采样与校准都限制在相应训练折内。原始概率评价应使用未人为平衡的留出分布，不能直接把类别加权后的分数解释为人群发病概率。
- 分病种报告 ROC-AUC、PR-AUC、敏感度、特异度、精确率、Brier 分数和校准情况，提供不确定性与适用人群说明；结合实际使用目的评价提醒阈值。
- 新模型分别确定输出校准与提醒阈值，不沿用 ICU 模型的 0.7151 阈值。若需要解释，展示模型相关因素，避免写成已确定的病因。
- 调查抽样、失访和就医可及性会影响标签与风险估计，应评估权重、选择偏倚及亚组表现。临床使用前还需贴近目标社区的独立评价。

参考：[TRIPOD+AI 临床预测模型报告与评价说明](https://www.bmj.com/content/385/bmj-2023-078378)。

可采用的接口约定：Python POST /predict/disease，Java POST /disease-risk/assess。每病输出 disease_code、outcome_definition、horizon_definition、probability、eligibility_status、data_quality_status、model_version；不能预测时 probability 为 null，不伪造为 0。

建议新增 elder_disease_history、elder_lab_result、disease_prediction_record；必要时扩展现有档案。原始研究受访者 ID 与网站用户 ID 分开管理，研究原始数据按使用协议存放，不直接灌入网站患者表。

当前 ICU 模型可保留为独立的实验生理预警模块。疾病风险模型在数据和评价完成后再成为新的主功能，避免把旧模型分数改名为疾病概率。
